    ZAP · Lesson 1 · Concepts

    What ZAP is and how it finds bugs

    ZAP (Zed Attack Proxy) is a free, open-source web application security scanner. It started as an OWASP flagship project, and since 2024 it is maintained by the original ZAP team with Checkmarx sponsorship. Many people still call it "OWASP ZAP".

    ~8 minBeginner

    ZAP is a man-in-the-middle proxy. Your browser sends traffic to ZAP, ZAP forwards it to the application, and every request and response is recorded on the way through. Once ZAP has seen the app, it can analyse that traffic and attack it.

    BrowserFirefox / Chrome launched by ZAP, or configured to use proxy localhost:8080
    →
    ZAP proxyRecords, inspects, edits and replays every request
    →
    Target web appOnly an app you own or have written permission to test

    The four things ZAP does

    • Explore the app: through your manual browsing, the traditional Spider (follows links in HTML) and the AJAX Spider (drives a real browser for JavaScript-heavy apps).
    • Passive scan every response it sees. Passive rules only read traffic, for example missing security headers or cookies without HttpOnly. Safe to run anywhere.
    • Active scan: sends attack payloads (SQL injection, XSS, path traversal and more) to each parameter. This changes data and can break things.
    • Report the alerts it raised, with risk, confidence, evidence and a fix.
    LegalActive scanning a site without written permission is illegal in most countries. Practice on deliberately vulnerable apps such as OWASP Juice Shop or DVWA running on your own machine.

    Set up a safe practice target

    shell · run Juice Shop locally
    docker run --rm -p 3000:3000 bkimminich/juice-shop
# then open http://localhost:3000
    ZAP · Lesson 2 · Setup

    Install ZAP and pick a mode

    ZAP runs on Windows, macOS and Linux. The installers bundle Java; the cross-platform package needs a recent Java (17 or later for current releases).

    ~6 minBeginner
    1. Download from zaproxy.org/download and install.
    2. On first launch, ZAP asks whether to persist the session. Choose a session file name if you want to keep your results; otherwise pick "do not persist".
    3. Open Tools → Options → Network → Server Certificates if you will proxy HTTPS from your own browser. Browsers launched from ZAP already trust its certificate.

    The ZAP window

    AreaWhat lives there
    Sites tree (left)Every host, folder and URL ZAP has seen
    Workspace (top right)Quick Start, Request and Response tabs
    Information panes (bottom)History, Search, Alerts, Output, Spider, Active Scan progress

    Modes control what ZAP is allowed to do

    ModeBehaviourUse it when
    SafeNo potentially harmful actions at allBrowsing a site you have no permission to attack
    ProtectedHarmful actions only on URLs inside a context's scopeRecommended default for real work
    StandardYou can do anything you chooseDefault on install
    ATTACKNew in-scope nodes are actively scanned as they are foundLab targets only
    TipSwitch the mode from the drop-down in the top-left toolbar. Protected mode plus a well-defined context is the simplest way to avoid scanning a third-party CDN or payment provider by accident.
    ZAP · Lesson 3 · First scan

    Run your first automated scan

    Quick Start's Automated Scan spiders the target, waits for passive scanning, then runs an active scan. It is the fastest way to see what ZAP can find.

    ~10 minBeginner
    1. Click Quick Start → Automated Scan.
    2. Enter the URL to attack, for example http://localhost:3000.
    3. Keep Use traditional spider on. Turn on Use ajax spider for single-page apps (Juice Shop is one), and pick a browser.
    4. Press Attack. Watch the Spider and Active Scan tabs fill up.
    5. Open the Alerts tab and click an alert to see the request, the evidence and the suggested solution.

    Reading an alert

    RiskMeaningTypical example
    HighLikely exploitable, serious impactSQL Injection, Remote OS Command Injection
    MediumExploitable with conditionsMissing anti-CSRF tokens, Content Security Policy not set
    LowWeakness that helps an attackerCookie without SameSite attribute
    InformationalNot a vulnerability by itselfModern web application detected

    Confidence (Confirmed, High, Medium, Low, False Positive) is separate from risk. A High-risk, Low-confidence alert needs manual verification before you report it. Right-click an alert and choose Mark as False Positive once you have ruled it out.

    LimitThe automated scan does not log in. Anything behind a login page is invisible to it until you set up authentication (Lesson 5).
    ZAP · Lesson 4 · Proxying

    Explore manually and intercept requests

    Spiders miss multi-step forms, file uploads and business flows. Clicking through the app yourself, with ZAP recording, gives the best coverage.

    ~12 minIntermediate

    Manual Explore

    1. Quick Start → Manual Explore, enter the URL, choose Firefox or Chrome, click Launch Browser.
    2. The browser is pre-configured to use ZAP and to trust its certificate. Optionally enable the HUD to see alerts overlaid on the page.
    3. Log in, fill every form, use every feature. Each request appears in History and the Sites tree.

    Breakpoints: pause and edit traffic

    Press the green breakpoint button in the toolbar (or Ctrl+B) to break on all requests. The next request stops in ZAP; change any value, such as a price, a user ID or a role, then press Submit and step or Continue.

    Resend and the Fuzzer

    • Right-click → Open/Resend with Request Editor replays a request with your edits. Good for testing one idea, such as changing userId=12 to userId=13 (an IDOR check).
    • Right-click → Attack → Fuzz: highlight a value, add payloads (built-in lists or a file), and ZAP sends one request per payload. Sort results by status code or response size to find the odd one out.
    TipUsing your own browser instead? Point its proxy at localhost:8080 and import ZAP's root CA certificate (Options → Network → Server Certificates → Save) so HTTPS sites load without warnings.
    ZAP · Lesson 5 · Scope

    Contexts, scope and authenticated scanning

    A context is a named set of URLs (regex include and exclude patterns) with its own authentication, session handling and users. Most real scans need one.

    ~15 minIntermediate

    Create a context

    1. In the Sites tree, right-click the host → Include in Context → New Context. ZAP adds a pattern such as http://localhost:3000.*.
    2. Add exclude patterns for anything dangerous to hit repeatedly: .*logout.*, .*delete.*, password change pages.
    3. Turn on Show only URLs in Scope in History and Alerts to hide noise.

    Teach ZAP to log in

    MethodFits
    Browser-basedMost modern apps. ZAP drives a real browser to fill the login form.
    Form-basedClassic POST login forms. Right-click the login request → Flag as Context → Form-based Auth Login Request.
    JSON-basedAPIs that log in with a JSON body.
    HTTP/NTLMBasic, Digest or NTLM authentication.
    Script-basedAnything unusual, such as multi-step or token exchange flows.

    Then, in the context's Users panel, add a test user with credentials, and set a logged-in indicator (a regex that only appears when signed in, such as \QLogout\E) or a logged-out indicator. ZAP uses these to detect that it has been logged out and to log in again.

    Finally, run the Spider and Active Scan with that context and user selected. Scan coverage usually jumps once authenticated pages are reachable.

    TipFor apps using bearer tokens, the Authentication Helper and "Auth Header" environment variables (ZAP_AUTH_HEADER_VALUE) let ZAP add a header to every request without scripting.
    ZAP · Lesson 6 · Tuning

    Passive vs active scans and scan policies

    An active scan with every rule at maximum strength can run for hours. Scan policies let you choose which rules run and how hard they push.

    ~10 minIntermediate
    Passive scanActive scan
    What it doesInspects traffic ZAP already sawSends new attack requests
    Risk to targetNoneCan create, change or delete data
    When it runsAutomatically, in the backgroundOnly when you start it
    FindsHeaders, cookies, info leaks, outdated librariesSQLi, XSS, path traversal, command injection, SSRF

    Build a policy

    1. Analyse → Scan Policy Manager → Add.
    2. Set a default Threshold (how sure a rule must be before alerting: Low, Medium, High) and Strength (how many requests a rule may send: Low, Medium, High, Insane).
    3. Turn off categories that do not apply, for example server-side rules for databases you do not use.
    4. Select the policy in the Active Scan dialog (right-click a node → Attack → Active Scan).
    TipInstall extra rules from the Marketplace (the three-box icon). "Beta" and "Alpha" active and passive scan rule add-ons add many checks that are not in the default release set.
    ZAP · Lesson 7 · Output

    Generate a report people will read

    A report should tell developers what to fix first. Clean out false positives and out-of-scope noise before you generate it.

    ~6 minBeginner
    1. Report → Generate Report.
    2. Pick a template: traditional-html, modern, risk-confidence-html, traditional-pdf, traditional-json, traditional-xml, or sarif-json for code-scanning tools.
    3. On the Filter tab, choose which risks and confidences to include, and limit to your context.

    What a good finding includes

    • The alert name and its CWE / WASC ID, which ZAP fills in.
    • The exact URL, parameter and attack string, plus the evidence ZAP matched.
    • Your own manual verification notes: did you reproduce it?
    • The fix, in the developer's language and framework.
    ZAP · Lesson 8 · DevSecOps

    Automate ZAP with Docker and CI

    The packaged Docker scans let you run ZAP on every build without opening the desktop app. The Automation Framework gives full control with one YAML file.

    ~15 minAdvanced
    ScriptWhat it doesSafe for production?
    zap-baseline.pySpider for 1 minute, passive scan onlyYes, no attacks
    zap-full-scan.pySpider, optional AJAX spider, full active scanNo, test environments only
    zap-api-scan.pyImports an OpenAPI, SOAP or GraphQL definition and actively scans the APINo, test environments only

    Try itDocker command builder

    shell
    
  
    
  
    Exit codes make these scripts CI-friendly: 0 no issues, 1 at least one FAIL, 2 at least one WARN, 3 any other failure. Generate a rules file with -g gen.conf, then change rules to IGNORE, WARN or FAIL and pass it back with -c gen.conf.
    
  
    Automation Framework plan
    
  
    yaml · zap-plan.yaml
    env:
  contexts:
    - name: "juice-shop"
      urls: ["http://localhost:3000"]
      includePaths: ["http://localhost:3000.*"]
      excludePaths: [".*logout.*"]
  parameters:
    failOnError: true
    progressToStdout: true
jobs:
  - type: passiveScan-config
    parameters:
      maxAlertsPerRule: 10
  - type: spider
    parameters:
      maxDuration: 2
  - type: spiderAjax
    parameters:
      maxDuration: 3
  - type: passiveScan-wait
  - type: activeScan
    parameters:
      maxScanDurationInMins: 15
  - type: report
    parameters:
      template: traditional-html
      reportDir: /zap/wrk
      reportFile: zap-report
    
  
    shell · run the plan
    ./zap.sh -cmd -autorun zap-plan.yaml
# or in Docker
docker run --rm -v "$(pwd)":/zap/wrk/:rw -t ghcr.io/zaproxy/zaproxy:stable \
  zap.sh -cmd -autorun /zap/wrk/zap-plan.yaml
    
  
    TipIn the desktop app, Tools → Automation Framework lets you build and test a plan visually, then save the YAML for CI. GitHub users can also use the official zaproxy/action-baseline and zaproxy/action-full-scan actions.

  JMeter · Lesson 1 · Concepts
  
    What Apache JMeter is and what it measures
    
  
    JMeter is a free, Java-based tool from the Apache Software Foundation for load and performance testing. It simulates many users sending requests and records how fast and how reliably the system responds.
    
  
    ~8 minBeginner
    

    

    
  
    JMeter works at the protocol level. It sends HTTP requests and reads responses, but it is not a browser: it does not run JavaScript or render pages. That is why one machine can simulate hundreds of users.
    
  
    Kinds of performance test
    
  
    
    
    TestQuestion it answersShape
    
    
    LoadDoes it meet targets at expected traffic?Ramp to normal peak, hold
    
    
    StressWhere does it break, and how?Keep increasing until errors climb
    
    
    SpikeDoes it survive a sudden burst?Jump from low to very high instantly
    
    
    Soak / enduranceDoes it degrade over hours (memory leaks, connection pools)?Moderate load for 4–24 h
    
  
    
  
    Protocols it can test
    
  
    HTTP/HTTPS (web and REST), SOAP, JDBC databases, FTP, LDAP, JMS message queues, SMTP/POP3/IMAP, TCP and Java code. More come from the JMeter Plugins Manager.
    
  
    The numbers you will report
    
  
      
    
    • Response time: average, median, and the 90th/95th/99th percentiles. Percentiles matter more than the average.
      • 
    
    • Throughput: requests per second the system handled.
      • 
    
    • Error %: share of failed samples.
      • 
    
    • Concurrent users (threads) at which those numbers were measured.
      • 
  
    

    

    

    


    

    

    
  JMeter · Lesson 2 · Setup
  
    Install JMeter and run it the right way
    
  
    Build tests in the GUI. Run real load from the command line. The GUI consumes memory and CPU and will distort your results.
    
  
    ~8 minBeginner
    

    

    
  
      
    
    1. Install a Java JDK (version 8 or later; 17 or 21 is a good choice). Check with java -version.
      2. 
    
    2. Download the binary zip from jmeter.apache.org and unzip it.
      3. 
    
    3. Start the GUI: bin/jmeter.bat on Windows or bin/jmeter on macOS and Linux.
      4. 
    
    4. Install the Plugins Manager by dropping its jar into lib/ext and restarting. It adds Options → Plugins Manager.
      5. 
  
    
  
    Run a test in non-GUI (CLI) mode
    
  
    shell
    jmeter -n -t checkout.jmx -l results.jtl -e -o report/
# -n  non-GUI mode
# -t  test plan file
# -l  raw results file (CSV .jtl)
# -e  generate HTML dashboard at the end
# -o  empty output folder for the dashboard
    
  
    Pass settings in from outside
    
  
    shell
    jmeter -n -t checkout.jmx -Jthreads=200 -Jrampup=120 -l run2.jtl
# inside the plan, read them with ${__P(threads,10)} and ${__P(rampup,30)}
    
  
    HeapFor bigger tests, raise the heap before starting: export HEAP="-Xms1g -Xmx4g" (Linux/macOS) or set HEAP=-Xms1g -Xmx4g (Windows).
    

    

    

    


    

    

    
  JMeter · Lesson 3 · Structure
  
    Anatomy of a test plan
    
  
    A test plan is a tree saved as a .jmx file. Where you place an element in the tree decides which requests it affects.
    
  
    ~12 minBeginner
    

    

    
  
    
Test Planroot
    
├─ HTTP Request Defaultsconfig
    
├─ HTTP Cookie Managerconfig
    
├─ Thread Group  (50 users, ramp-up 60 s)threads
    
│  ├─ Uniform Random Timertimer
    
│  ├─ GET /homesampler
    
│  ├─ POST /loginsampler
    
│  │  ├─ JSON Extractor → tokenpost-processor
    
│  │  └─ Response Assertion (200)assertion
    
│  └─ GET /orderssampler
    
└─ Summary Reportlistener
  
    
  
    
    
    ElementJob
    
    
    Thread GroupThe virtual users: how many, how fast they start, how long they run
    
    
    SamplerSends one request (HTTP Request, JDBC Request, etc.)
    
    
    Logic ControllerControls flow: Loop, If, While, Transaction, Once Only, Random
    
    
    Config ElementShared settings and data: defaults, headers, cookies, CSV data
    
    
    TimerAdds think time between requests
    
    
    Pre / Post-ProcessorRuns before / after a sampler, e.g. extracting a token
    
    
    AssertionMarks a sample failed if the response is wrong
    
    
    ListenerCollects and shows results
    
  
    
  
    Execution order for each sampler
    
  
      
    
    1. Config elements
    2. Pre-processors
    3. Timers
    4. Sampler
    5. Post-processors
    6. Assertions
    7. Listeners
      8. 
  
    
  
    Scoping rule: an element applies to samplers at its own level and below. A timer placed directly under the Thread Group delays every sampler in it; a timer placed under one sampler delays only that sampler.
    

    

    

    


    

    

    
  JMeter · Lesson 4 · Load model
  
    Thread groups and load math
    
  
    Threads are not requests per second. Throughput depends on how long each request takes plus the think time between them.
    
  
    ~12 minIntermediate
    

    

    
  
    
    
    SettingMeaning
    
    
    Number of Threads (users)Concurrent virtual users
    
    
    Ramp-up period (s)Time to start all threads. 100 threads over 50 s = 2 new users per second
    
    
    Loop Count / InfiniteHow many times each user repeats the flow
    
    
    Specify thread lifetime → DurationStop after N seconds, regardless of loops
    
  
    
  
    The steady-state rule of thumb (Little's Law): throughput ≈ users ÷ (response time + think time).
    
  
    
    
    Try itLoad calculator
    
    
    
      
    
      
    
      
    
      
    
      
    
    
    
    
    
      
    –
    req/s at steady state
    
      
    –
    users started per second
    
      
    –
    approx. total requests
    
      
    –
    requests per minute
    
    
    
  
    
  
    Other thread groups
    
  
      
    
    • setUp / tearDown Thread Group: run before and after the main test, e.g. to create and delete test data.
      • 
    
    • Concurrency Thread Group / Ultimate Thread Group (plugins): step and hold patterns, useful for stress tests.
      • 
    
    • Open Model Thread Group (built in since 5.5): schedule arrivals like rate(10/sec) random_arrivals(5 min) instead of fixed users.
      • 
  
    

    

    

    


    

    

    
  JMeter · Lesson 5 · Hands-on
  
    Build an HTTP test from scratch
    
  
    A small REST flow: open the home page, log in, list orders. Five elements cover most web tests.
    
  
    ~15 minBeginner
    

    

    
  
      
    
    1. Right-click Test Plan → Add → Threads → Thread Group. Set 10 threads, 10 s ramp-up, loop 5.
      2. 
    
    2. Add → Config Element → HTTP Request Defaults: protocol https, server api.example.test. Every sampler inherits these.
      3. 
    
    3. Add → Config Element → HTTP Header Manager: Content-Type: application/json.
      4. 
    
    4. Add → Config Element → HTTP Cookie Manager so each user keeps its own session cookies.
      5. 
    
    5. Add → Sampler → HTTP Request three times: GET /, POST /api/login, GET /api/orders.
      6. 
    
    6. Add → Listener → View Results Tree and Summary Report. Press the green Run button.
      7. 
  
    
  
    Login request body
    
  
    json · Body Data tab
    {
  "username": "${user}",
  "password": "${pass}"
}
    
  
    Recording instead of building by hand
    
  
    Templates → Recording creates a plan with the HTTP(S) Test Script Recorder on port 8888. Point your browser's proxy at it, import ApacheJMeterTemporaryRootCA.crt from the bin folder, press Start, and use the site. JMeter writes samplers for each request. Clean out analytics and static files afterwards.
    
  
    CarefulView Results Tree stores every response in memory. Use it while debugging with one or two users, then disable it before a real load run.
    

    

    

    


    

    

    
  JMeter · Lesson 6 · Realism
  
    Test data, variables and correlation
    
  
    100 users logging in as the same account do not behave like 100 real users. Feed in different data, and capture dynamic values the server sends back.
    
  
    ~15 minIntermediate
    

    

    
  
    CSV Data Set Config
    
  
    csv · users.csv
    user,pass
alice,Secret#1
bob,Secret#2
carol,Secret#3
    
  
    Add Config Element → CSV Data Set Config, set Filename users.csv, leave Variable Names empty to use the header row, and set Recycle on EOF and Sharing mode as needed. Each thread reads the next line and ${user} / ${pass} change per iteration.
    
  
    Useful functions
    
  
    
    
    FunctionReturns
    
    
    ${__Random(1,500)}Random integer in a range
    
    
    ${__UUID()}Random UUID
    
    
    ${__time(yyyy-MM-dd)}Current date in a format
    
    
    ${__threadNum}Number of the current thread
    
    
    ${__P(name,default)}Property passed with -Jname=value
    
  
    
  
    Correlation: capture, then reuse
    
  
    Login returns {"token":"eyJhbGci..."}. Later requests need it. Add a JSON Extractor under the login sampler:
    
  
    
    
    FieldValue
    
    
    Names of created variablestoken
    
    
    JSON Path expressions$.token
    
    
    Default valuesTOKEN_NOT_FOUND
    
  
    
  
    Then add a Header Manager to later requests with Authorization: Bearer ${token}. For HTML responses (CSRF tokens, view state), use the Regular Expression Extractor or Boundary Extractor, e.g. regex name="csrf" value="(.+?)" with template $1$.
    
  
    DebugAdd a Debug Sampler and look at it in View Results Tree to see every variable's current value. A default value like TOKEN_NOT_FOUND showing up in a request tells you the extractor failed.
    

    

    

    


    

    

    
  JMeter · Lesson 7 · Accuracy
  
    Assertions and timers
    
  
    A server that answers "200 OK" with an error page is not a pass. A user who never pauses is not a real user. Assertions and timers fix both.
    
  
    ~10 minIntermediate
    

    

    
  
    Assertions
    
  
    
    
    AssertionChecks
    
    
    Response AssertionStatus code, text or regex in the body or headers
    
    
    JSON AssertionA JSON path exists or equals a value, e.g. $.status = ok
    
    
    Duration AssertionResponse took no longer than N ms (an SLA check)
    
    
    Size AssertionResponse size in bytes
    
  
    
  
    Timers
    
  
    
    
    TimerUse for
    
    
    Constant TimerFixed pause, e.g. 2000 ms
    
    
    Uniform Random TimerPause = constant offset + random range. Realistic think time
    
    
    Gaussian Random TimerPauses clustered around an average
    
    
    Constant Throughput TimerHold a target rate in samples per minute
    
    
    Precise Throughput TimerTarget rate with Poisson-style arrivals
    
  
    
  
    NoteTimer delay is not included in the response time JMeter reports, but it does lower throughput. Wrap a flow in a Transaction Controller to measure the whole flow as one transaction.
    

    

    

    


    

    

    
  JMeter · Lesson 8 · Analysis
  
    Read the results and scale out
    
  
    The HTML dashboard turns a .jtl file into charts and tables. Learn which numbers to quote, and how to add more load generators when one machine is not enough.
    
  
    ~14 minAdvanced
    

    

    
  
    Dashboard from an existing results file
    
  
    shell
    jmeter -g results.jtl -o report/
    
  
    What to look at
    
  
    
    
    MetricHealthy signWarning sign
    
    
    APDEXClose to 1.0Below 0.7
    
    
    95th / 99th percentileWithin your SLAFar above the median: a long tail
    
    
    Throughput over timeRises with users, then flatFlat or falling while users rise: saturation
    
    
    Error %Near 0Grows with load
    
    
    Response time vs threadsFlatKnee in the curve: the capacity limit
    
  
    
  
    Monitor the servers too (CPU, memory, DB connections, GC pauses) and the load generator itself. If the JMeter machine runs above about 80% CPU, your numbers describe JMeter, not the app.
    
  
    Distributed testing
    
  
      
    
    1. Install the same JMeter and Java version on every machine. Copy CSV files to each.
      2. 
    
    2. Start jmeter-server on each worker. Recent versions need RMI SSL keys (create-rmi-keystore) or server.rmi.ssl.disable=true on a trusted network.
      3. 
    
    3. List workers in remote_hosts in jmeter.properties, or pass them with -R.
      4. 
  
    
  
    shell · controller
    jmeter -n -t checkout.jmx -R 10.0.0.11,10.0.0.12 -l dist.jtl -e -o report/
# each worker runs the full thread count: 2 workers x 100 threads = 200 users
    
  
    CIRun the CLI command in Jenkins, GitLab CI or GitHub Actions, then fail the build on thresholds with a Duration Assertion or by parsing statistics.json in the report folder.
